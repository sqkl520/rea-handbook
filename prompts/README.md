# 提示词模板

让 AI 帮你做逆向学习的提示词。复制正文、替换占位符、粘贴给任何有文件系统和命令行的 AI。

> ⚠️ **仅对你有权分析的目标使用**（你自己的软件、开源项目、你购买并有权分析的产品）。

## 文件与模板的对应

两个文件里其实装了**三份**提示词，注意对应关系：

| 文件 | 内含 | 用途 |
| --- | --- | --- |
| [`reverse-engineer-learning.md`](reverse-engineer-learning.md) | 一份**完整版**（约 250 行） | 要把学到的东西用在自己项目上：结论 + **可借鉴性**（可直接借鉴 / 需改造 / 不能照搬） |
| [`reverse-engineer-learning-minimal.md`](reverse-engineer-learning-minimal.md) | ① 一份**纯学习版**主提示词（约 170 行）<br>② 一份**约 700 字的精简版**（文件后半段） | 纯粹看懂 + 学到：结论 + **做得好的地方**（是什么 / 解决什么问题 / 妙在哪 / 代价） |

`-minimal.md` 这个文件名指的是**输出取向**（不要求映射回自己项目），不是篇幅——
它比完整版只短 8%，因为里面多装了一份 700 字短版。

**选择建议**：
- 只想搞明白“这东西怎么做的”，粘贴一次了事 → 用 `-minimal.md` 后半段的 **700 字版**
- 只想搞明白，但愿意多轮追问 → 用 `-minimal.md` 前半段的**纯学习版主提示词**
- 要写进自己项目 → 用 `reverse-engineer-learning.md`
- 目标很大（几百 MB、几千个类型）→ 用完整版，并且**别省掉交叉验证那一步**

## 怎么用

1. 打开对应文件，复制**最外层** ` ````text ` 围栏内的全部内容。
   注意是**四个**反引号：正文里还嵌着 ``` 围栏的代码块，用三个反引号会截断。
2. 替换占位符（`<>` 形式，全文件替换）：
   - `<目标路径>` → 应用的绝对路径
   - `<要学的功能>` → 比如“多版本管理”“下载系统”“UI 主题机制”
   - `<你的项目路径>` → 你的项目路径（**仅完整版需要**；精简版没有这个占位符）
3. 粘贴给 AI

**示例（填好的样子）**：

```text
逆向分析 <目标路径>，搞懂它的「多版本管理与实例隔离」，
最后告诉我对我的项目（<你的项目路径>，Android/Kotlin）有什么可借鉴的。
（其余照抄）
```

## 这两个模板为什么长这样

它们是**从真实逆向中提炼的**——包括踩过的坑和绕过的弯路。

### 三条核心要求

**① 先侦察再动手**

不同技术栈的分析路径**完全不同**：
- .NET 程序集 → 可以全量反编译，最容易读
- 原生二进制 → 需要 Ghidra/IDA
- Electron 应用 → 可以直接读 JS
- Go/Rust → 有专用的元数据检查

**跳过侦察会走错路线，浪费最多时间。**

**② 标注证据等级**

每条结论要标【观测】（看到源码/反汇编/字符串原文）还是【推断】（根据结构猜的）。

这不是形式主义——**不标注的结论会被下游当事实用**，而"推断"经常是错的。

**③ 交叉验证关键结论**

**名字会骗人，字段和方法不会。**

真实案例：一份分析里按类型名把 `PageLinkMain` 当成"主页"，
实际它的私有字段是 `NATType` / `NetworkSecret`，邀请码由 `GetInviteCode()` 现拼——是**联机页**；真正的主页是另一个类型（`PageLaunchRight`）。

同项目第二个例子：`MySkin` 看着像主题引擎，实际是**皮肤预览控件**。

**所以模板要求：拿到可疑的类型，先看它的字段和方法，不要信名字。**

### 为什么强调"字符串扫描"

**成熟软件的日志文案就是它自己写的文档。**

真实案例：一个启动器的下载流程，是从字符串常量的**顺序**读出来的：

```
"分析支持库文件" → "下载支持库文件" → "分析资源索引" → "下载资源索引"
```

阅读方法字符串 = 阅读执行流程。**产出/成本比最高的一步。**

### 为什么要求"讲清为什么"

只描述"它做了什么"是**没用的**——那个看源码就知道了。

有价值的是回答三个问题：
1. 它解决什么问题？（想象没有它会怎样）
2. 为什么用这个方案而不是更简单的？
3. 代价是什么？（性能、复杂度、维护性）

## 配套：多 Agent 的用法

两个模板都允许 AI 开子 agent。**但切分方式很重要**：

```
✅ 好的切分（各有独立结论）：
  · agent 1：功能 A 的完整链路
  · agent 2：功能 B 的完整链路
  · agent 3：UI / 呈现层
  · agent 4：错误处理与诊断

❌ 坏的切分（互相重复、结论碎片化）：
  · agent 1：分析前 100 个文件
  · agent 2：分析后 100 个文件
```

**按"功能维度"切，不按"文件"切。**

给每个子 agent 的任务书里必须包含：
1. 已确认的**事实**（避免它重新发现，也避免它基于错误前提）
2. **证据等级要求**
3. **可用的工具和已知的坑**
4. **它该产出什么格式**

## 一个诚实的提醒

**模板里的"做得好"要如实评价。**

如果分析下来发现某处其实很平庸、或者有更好的做法，就直说。
**吹捧没有学习价值**——一份好的学习报告里，
"它这里其实做得不好"往往比"它这里很棒"更有用。
